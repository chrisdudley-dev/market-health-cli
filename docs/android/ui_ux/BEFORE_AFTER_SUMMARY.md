# Before and after

The before capture is source 54937ab (required lifecycle fix already present) on a 360 dp S9+-class emulator. It is dark-only because the prior UI had no light theme. It is separate from the original failed physical battery candidate and does not replace that evidence.

The new UI adds light/dark/system appearance, semantic surfaces and typography, four primary navigation targets plus a complete drawer, a compact Dashboard overview, readable score bars, structured symbol detail/audit, display-only filtering/sorting, recorded-point history charts/timeline, grouped settings and confirmed portfolio removal.

The original dense numeric text is replaced with readable one-decimal score labels while exact stored values remain in audit and parity tests. GlyphSpec stays auditable in details rather than driving the ordinary presentation. All eight destinations and their original membership semantics remain.

Screenshot fixtures are synthetic presentation data drawn from unchanged approved Android fixture scores/reasons. History repeats those values at explicitly synthetic times to exercise layout; these are not authentic historical market observations or new performance evidence. The original before capture used persisted instrumentation fixture state. Consequently screenshots compare layout, not financial performance or identical portfolio populations.

No financial mathematics, policy thresholds, reason meanings, rescue consumption, sizing formula, universe, CLI behavior or persistence schema changes. The only Python bridge addition is read-only optional presentation metadata. Android foreground state reconciliation and UI callbacks change presentation/lifecycle behavior, with separate regression evidence.

All visual evidence is rendered by the actual Android Compose runtime. No screenshot is painted over or re-created as a mockup. See evidence/after and RESPONSIVE_LAYOUT.md for profile and artifact identity.
